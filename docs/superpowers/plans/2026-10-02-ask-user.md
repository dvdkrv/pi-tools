# ask_user tool (v0.6.0)

An `ask_user` tool lets an agent ask the user one question with discrete choices in a TUI dialog. The answer comes back as the tool result, so the run continues at once.

## Task 1: `src/work/ask-user.ts` (pure module, no Pi runtime imports beyond types, pi-tui, and typebox)

Exports, with these exact names:

- `ASK_USER_DESCRIPTION`: "Ask the user one question with 2 to 6 discrete options and wait for the answer, which comes back as this tool's result. Use it for decisions with discrete options; mark the option you recommend with `recommended`. For open-ended discussion, write normal text and end with session_status needs-me instead."
- `ASK_USER_DISMISSED = "The user dismissed the question; ask in plain text or proceed without it."`
- `ASK_USER_NO_UI = "ask_user cannot show a dialog in this session. Ask the question in plain text instead and end with session_status needs-me."`
- `AskUserParams` (typebox `Type.Object`):
  - `question`: string, minLength 1, maxLength 300
  - `options`: array of 2 to 6 items, each `{ label: string, minLength 1, maxLength 60; description?: string, maxLength 120 }`
  - `recommended`: optional integer, minimum 0, the 0-based index into `options` (its schema description says so)
  - `allow_other`: optional boolean, default true (adds "Type something else…")
  - `context`: optional string, maxLength 600, shown above the question
- `type AskUserInput = Static<typeof AskUserParams>`
- `type AskUserAnswer = { kind: "option"; index: number; label: string } | { kind: "other"; text: string } | { kind: "dismissed" }`
- `askUserProblem(input): string | undefined` returns a message when `recommended` is out of range, and `undefined` otherwise.
- `askUserNote(input): string` is the session note: `<question> [<label1> / <label2> / …]`, one line, at most 200 characters (`NOTE_MAX` from `./types.ts`). When it is too long, shorten the question with "…" and keep the option list. If the option list alone is too long, shorten the whole note with "…".
- `answerText(answer): string`:
  - option: `The user chose "<label>" (option index <index>).`
  - other: `The user answered in their own words: <text>`
  - dismissed: `ASK_USER_DISMISSED`
- `askUserComponent(input, tui: { requestRender(): void }, theme, done: (answer: AskUserAnswer) => void)` returns `{ render(width): string[]; invalidate(): void; handleInput(data: string): void }`. `theme` needs only `fg(color, text)` and `bold(text)`.
  - Layout: an accent border (`DynamicBorder` from pi-coding-agent, as in `src/work/triage-ui.ts`, or a plain `─` repeat). Then the context in muted text, wrapped, if given, and a blank line. Then the question in bold and wrapped. Then a blank line. Then each option: `> ` prefix when selected (accent), otherwise two spaces, followed by `<n>. <label>` (n is 1-based for display), with ` (recommended)` after the recommended label. The description goes on the next line, indented and muted. When `allow_other` is not false, a last row reads `Type something else…`. Then a hint line (dim): `j/k move • enter choose • esc dismiss`. While editing it reads `enter submit • esc back`. Then a border. Every line is truncated to `width` (`truncateToWidth` from pi-tui).
  - Selection starts at `recommended` when it is valid, otherwise 0.
  - Keys: decode with `parseKey` from pi-tui, then use `keyStep`, `INITIAL_KEY_STATE`, and `moveIndex` from `./keymap.ts`, with `{ actions: [] }`, as `triage-ui.ts` does. Moves (j/k, arrows, gg/G, ctrl+d/u) change the selection. `enter` on an option calls `done({ kind: "option", index, label })`. `enter` on the "something else" row switches to inline text entry. `close` (esc or q) calls `done({ kind: "dismissed" })`. Call `tui.requestRender()` after every change.
  - Inline text entry uses pi-tui's `Input` component, rendered below the options after a muted `Your answer:` line. In this mode, raw input goes to the `Input`, except esc, which leaves text entry, clears the text, and returns to the options. Pressing Enter with non-empty trimmed text calls `done({ kind: "other", text: trimmed })`. Pressing Enter with empty text leaves text entry.
  - Index digits 1–9 are not required.

Tests go in `tests/work/ask-user.test.mjs`. They use `load` from `./helpers.mjs` and a fake theme (`fg: (_c, s) => s`, `bold: (s) => s`). They drive `handleInput` with raw sequences (`"j"`, `"\x1b[B"`, `"\r"`, `"\x1b"`, `"gg"` as two calls, `"G"`) and assert on `render(80)` output and on the `done` calls. They cover:

- the recommended option is marked and pre-selected
- j/k and the arrow keys move, clamped at the ends
- Enter chooses (0-based index and label)
- the other row opens text entry; typing and Enter returns the trimmed text; Esc in text entry returns to the options without calling `done`
- with `allow_other: false`, there is no other row
- Esc dismisses
- the context renders above the question
- `askUserNote` covers both length cases
- `askUserProblem` and `answerText` for each kind

## Task 2 (lead): tracker and wiring

- `SessionTracker.asking(note)` sets the status to `needs-me` with source `agent` and returns the session. `answered()` sets it to `working`/`auto`/empty.
- `extensions/work.ts` registers `ask_user` only outside child runs, with `exposure: "model-only"`. Non-TUI sessions deactivate it at session start. `execute` returns `ASK_USER_NO_UI` when `ctx.mode !== "tui"` or `!ctx.hasUI`. It calls `asking`, then notifies (with the same checks as agent_settled), shows `ctx.ui.custom`, and calls `answered` in `finally`.
